# `<pf-button>`


A button, with the variants, sizes and loading state the React `Button` has.

`type="submit"` and `type="reset"` act on the form around it, as a native
button's do. ARIA a wrapper sets on the host -- `aria-expanded`,
`aria-haspopup`, `aria-pressed` -- is copied to the real button inside, which
is the one a screen reader lands on. `delegatesFocus` is why focusing the
host reaches that button, which is what lets `pf-toolbar` treat it as an
item.

## Properties

| Property | Attribute | Type | Default | Description |
| --- | --- | --- | --- | --- |
| `disabled` | `disabled` | `boolean` | `false` | Disable the button. |
| `fullWidth` | `full-width` | `boolean` | `false` | Stretch to the width of the container. |
| `label` | `label` | `string \| undefined` | — | Accessible name, for when the slot holds only an icon. |
| `loading` | `loading` | `boolean` | `false` | Show a spinner and block interaction. |
| `size` | `size` | `"lg" \| "md" \| "sm"` | `'md'` | Control size. Reflected so the stylesheet can select on it. |
| `type` | `type` | `"button" \| "reset" \| "submit"` | `'button'` | Mirrors the native attribute. `submit` submits the form the host is in (running its validation, as `requestSubmit()` does) and `reset` resets it. The submitter is not reported in the submission: a custom element cannot be a form's submitter, so a `name`/`value` pair on it would go nowhere. |
| `variant` | `variant` | `"destructive" \| "ghost" \| "primary" \| "secondary"` | `'primary'` | Visual style. Reflected so the stylesheet can select on it. |
