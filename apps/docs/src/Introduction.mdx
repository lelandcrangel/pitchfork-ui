## Get started

Install the elements:

```bash
npm install @pitchfork-ui/elements
```

Import the stylesheet once at your app's entry point, register the elements, and
use them anywhere — including in plain HTML:

```js
import '@pitchfork-ui/elements/styles.css';
import { defineCustomElements } from '@pitchfork-ui/elements/loader';

defineCustomElements();
```

```html
<pf-button variant="primary">Get started</pf-button>
```

The stylesheet carries the design tokens, so there is no separate theme package
to install, and each element's own CSS travels with it into its shadow root.

For a framework, the generated binding packages add typed props and real event
handlers over the same elements. They are generated from the elements on every
build, never hand-written, so they cannot drift from what they wrap:

```bash
npm install @pitchfork-ui/elements-react    # or -angular, or -vue
```

```tsx
import { PfButton } from '@pitchfork-ui/elements-react';

<PfButton variant="primary">Get started</PfButton>;
```

See **Web components** for the install options in full, the
custom-property-versus-`::part()` split, and the handful of places the element
API deliberately differs from the React one it replaces.

## Explore the docs

- **Foundations** — design tokens, color, typography, theming, and dark mode.
- **Components** — all 108 elements, each with a reference page and an interactive playground.
- **Patterns** — complete compositions like login, settings, pricing, and checkout.
- **Web components** — installing them, the custom-property-versus-`::part()` split, and where the element API differs from the React one on purpose.
- **Migrating** — moving off the deprecated `@pitchfork-ui/react`, component by component, with a codemod for the mechanical part.
- **Changelog** — release history, generated from the published package.
- **Using with AI** — the MCP server, `llms.txt` and `metadata.json`, so a coding
  agent works from the library's real API instead of guessing at it.

Use the **theme toggle** on interactive stories to preview any component in light or
dark mode, and the **CSS Variables** panel to experiment with token overrides live.
